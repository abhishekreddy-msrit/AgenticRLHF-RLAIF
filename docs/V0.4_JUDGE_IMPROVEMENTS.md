## 1. What changed and why

| Change | Why |
|---|---|
| Rule-based score repair (`src/judge/scoring.py`) | LLM Pass-A regularly assigned safety=2 to good answers / treated refusals as violations |
| Independent rule verifier + Pass-B merge (`src/judge/verifier.py`) | Pass-B rubber-stamped bad drafts; rules now overturn first-pass scores |
| Final score clamp after Pass-B | Pass-B could reintroduce bad scores after rules fixed them |
| Preferred-response repair (meta / cosmetic / failure-mode inconsistent) | Chosen answers were often meta-commentary or near-copies with `[Improved…]` |
| Stricter preference eligibility | Contaminated / weak / cosmetic / harmful-chosen pairs were training-eligible |
| Preference quarantine columns (no deletes) | Legacy DB had heuristic, smoke_seed, and dangerous chosen text |
| Training uses `list_training_preferences()` only | Prevent silent ingest of quarantined/legacy junk |
| Retrieval prefers principles over prior prefs/evals | Chroma was echoing contaminated preference/eval docs |
| Behavioral primary metric (`behavioral_metrics.py`) | Before/after relied on the same judge’s overall score |
| Uniform low-score JSON accepted | `_coerce_scores_dict` previously discarded valid all-1/all-2 vectors → heuristic fallback |

**Not done (by design):** no LangGraph/MCP; no new large model download; GPU not used (driver unavailable).

## 2. New supervisory evaluation flow

```
prompt + target response
        │
        ▼
retrieve principles (prefer safe-*/examples) + history + rubric
        │
        ▼
behavioral precheck (deterministic)
        │
        ▼
Pass-A LLM JSON scores/critique/preferred
        │
        ▼
behavior guards + rule verifier (independent)
        │
        ▼
Pass-B adversarial LLM (sees RULE_VERIFIER_FINDINGS)
        │
        ▼
merge: rules win on contradictions; re-validate Pass-B scores
        │
        ▼
preferred repair (meta/cosmetic/failure-mode) + final score clamp
        │
        ▼
structural verify + confidence calibrate
        │
        ▼
preference eligibility → trusted save OR reject (never heuristic train)
```

Modes remain: `llm` | `hybrid` | `heuristic_fallback` (fallback never training-eligible).

## 3. Audit failures now addressed

| Prior failure | Now |
|---|---|
| Harmless helpful scored safety=2 | Final clamp forces safety≥4 |
| Appropriate refusal treated as unsafe / “violation” | Guards raise safety; false refusal-violations stripped |
| Over-refusal not lowering helpfulness | helpfulness≤2 enforced |
| Under-refusal not forcing low safety | safety≤1/2 enforced |
| Fabrication/jailbreak → heuristic via uniform-score reject | Uniform scores accepted; rules repair |
| Pass-B `agree:true` on bad drafts | Rules override; Pass-B cannot re-break critical dims |
| Cosmetic `[Improved…]` prefs | Detected + blocked; preferred replaced with principle-grounded text |
| Meta “The response is…” as preferred | Detected + replaced |
| smoke_seed / judge_fallback training-eligible | Quarantined + source gate |

## 4. Verification independence

1. **Behavioral precheck** — regex/intent cues, no LLM.  
2. **Rule verifier** — compares Pass-A scores to behavioral evidence; produces `corrected_scores` without asking the judge to agree with itself.  
3. **Pass-B** — adversarial prompt + must incorporate rule findings; suggestions re-checked by rules.  
4. **Structural verifier** — schema/identical-pair/safety-vs-overall.  
5. **Authority field** — `rules_override_llm` vs `consensus` is visible in outputs.

This is still not a second independent foundation model; independence is **methodological** (deterministic policy checks vs generative self-affirmation).

## 5. Preference quality / data integrity

Eligibility now requires (among other checks):

- confidence ≥ `JUDGE_MIN_CONFIDENCE` (0.52)
- not heuristic / not smoke_seed / not judge_fallback
- not identical or cosmetic
- not meta-judgment chosen
- not harmful chosen
- rationale present
- retrieval principle ids present
- sufficient chosen/rejected contrast
- target not already adequate (blocks low-signal pairs)

New DB columns: `training_status`, `quarantine_reason` (original rows preserved).
