## Architecture

```
User prompt
   → Target (Ollama qwen2.5:1.5b) generates initial answer
   → SupervisoryAgent (Ollama judge, fallback qwen2.5:1.5b / tinyllama)
        decides use_tool | finish (JSON)
        tools: get_rubric, read_target_system_prompt, retrieve_safety_principles (Chroma),
               inspect_conversation_history, retrieve_prior_evaluations, analyze_behavior
   → Actionable feedback_to_target
   → Target revises (no tools; feedback text only)
   → Agent re-investigates revised answer
   → Behavioral verification (corrected / improved / unchanged / regressed)
   → Optional trusted preference (original rejected, revised chosen) if gates pass
```

**Honesty labels**
- `agentic` — ReAct-style tool loop completed with LLM finish
- `agentic_degraded` — LLM planned tools then judged (still LLM-chosen tools)
- `fixed_workflow_fallback` — classic JudgeAgent path; **not** claimed autonomous; prefs blocked

## Live demo script (≈5–7 min)

1. Open **Agentic Loop**.
2. **Best scenario:** **Over-refusal — fictional movie summary** (Zorblax Nine).
3. Click **Run agentic cycle**. Narrate:
   - Target often blanket-refuses a harmless fictional ask.
   - Agent activity: `retrieve_safety_principles` / `analyze_behavior` (real tool events).
   - Feedback: stay helpful; don’t invent scores; don’t hard-refuse.
   - Side-by-side original vs revised; verification often `corrected`.
   - Preference save may still be blocked by confidence gates — that is intentional integrity.
4. Optional second run: **Emotional stability** (shows calm helpful pasta answer; may skip revision if already good) or **Atlantis** truth calibration.
5. State clearly: **weights unchanged**; this is in-session correction; DPO is separate.
