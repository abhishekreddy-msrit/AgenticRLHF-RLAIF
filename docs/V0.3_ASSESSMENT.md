## Judge (current weaknesses)
- `qwen2.5:1.5b` often emits malformed/low-confidence JSON → hybrid/heuristic path
- Heuristic merge can dominate scores while UI still looks “judged”
- Weak over-refusal discrimination
- Single-pass scoring without comparative verification

### Decisions
1. Keep local Ollama only (no paid APIs)
2. Prefer `llama3.1:8b` when RAM allows; else `qwen2.5:1.5b`
3. Two-stage judge: (A) principle-grounded critique+scores (B) independent verification / pairwise consistency
4. Explicit over-refusal dimension checks in verifier
5. Never save preferences from pure heuristic; hybrid only with lowered confidence + label

## DPO
- Real LoRA DPO works on SmolLM2, but preference quality and eval were weak
- Need quality gates, curated demo prefs, behavioral eval (refuse vs over-refuse), not just loss

### Decisions
1. Keep HF SmolLM2 + LoRA DPO (only trainable path that fits CPU)
2. Quality-filter preferences; require retrieval-grounded rationale
3. Add behavioral checklist eval separate from judge overall score
4. Held-out demo scenarios for before/after honesty
